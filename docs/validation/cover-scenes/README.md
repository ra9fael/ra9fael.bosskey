# 封面场景实测：D3D11 唯一后端 + 代码雨 / gcc 改动

本次把渲染后端收敛为 D3D11——软件光栅不渲染 `ShaderEffect`，见
[../shader-backend-probe](../shader-backend-probe)——并改了代码雨与 gcc 两个场景。
五个场景在 D3D11 下逐一截图确认过（蓝屏中文与二维码、更新 spinner、gcc 日志、
代码雨、黑洞）均正常，下面是两处改动的证据。

## 代码雨：片假名 + 数字 + 拉丁字母（不含汉字）

`matrix.png`：全屏实拍（缩到 1280×720、256 色）。字符集是半角片假名、数字和大小写
拉丁字母，一种字宽，列距均匀，字形在格子里居中。

汉字被移除，因为它就是开场那一下卡的来源。在 480×270 预览里给 `MatrixScene.onPaint`
打点（`--cover matrix --windowed`，同一进程取前 14 帧）：

| 帧 | 含汉字 | 去掉汉字后 |
|---|---|---|
| 第 1 帧 | 360 ms | 142–316 ms |
| 第 3–4 帧（≈0.5 s，新字形入画） | **841 ms** | 0 ms |
| 之后每帧 | 0–1 ms | 0–1 ms |

拆开第 1 帧：`getContext` 1 ms、`fillRect` 0 ms、`ctx.font` **140 ms**、`measureText` 1 ms、
绘制 0 ms。也就是一次性成本全在字体上：

- `ctx.font = "bold 20px 'MS Gothic', 'Microsoft YaHei', 'SimSun', monospace"` 的回退链要加载
  两个字体文件：`msgothic.ttc`（片假名，必需）和 `msyh.ttc`（15 MB 量级，汉字）；
- 汉字不在 MS Gothic 里，每个**新**汉字第一次落笔时都要走回退引擎并当场光栅化——
  这些字形是随列移动陆续进入画面的，所以卡顿不是一次，而是散在前一两秒的几帧里，
  第 4 帧那 841 ms 就是一次集中结算。

去掉汉字后回退链只剩 `'MS Gothic', monospace`，第二次卡顿整段消失；首帧剩下的
≈140 ms 是 MS Gothic 自身的加载，片假名要用它，除非连片假名一起去掉。

（对照实验：把字体名改成不存在的家族，同一行要 990 ms——DirectWrite 得枚举整个字体集
才发现它不存在。可见这一行的成本确实是字体解析，不是画布初始化：`getContext` 与
`fillRect` 都是 0–1 ms。）

## gcc：无限滚动 + 长行换行

同一次覆盖内的三帧（480×270 窗口，`--autohide 90`）：

| 时刻 | 截图 | 画面 |
|---|---|---|
| 6 s | `gcc-t6.png` | 第一趟编译后段，70%–76% |
| 51 s | `gcc-t51.png` | 第二趟，56%–64% |
| 71 s | `gcc-t71.png` | 第三趟，32%–42% |

百分比在一趟之内爬到 96% 就交棒给下一趟（CMake 重新生成），不链接、不出现 100%：
覆盖要挂多久都还有东西在滚。`gcc-wrap.png` 是换行特写：长路径与长警告在窗口边缘
换行，和真终端一样；警告行保持琥珀色。
