# 黑洞入场实测：先桌面，再长大

`boss blackhole`（`--cover blackhole`）每次显示都从桌面开始：封面刚出现时是**原样的桌面**
——相当于所有应用最小化——随后黑洞在屏幕正中从亚像素长到满尺寸，吸积盘同步升温、变亮，
最后落到原来的稳态。

## 画面

三帧来自同一次覆盖（全屏 1920×1080，`python tools/verify/shot.py <png> --at 0.8,3,8`
按封面出现后的墙钟时间连拍；存盘时缩到 1280×720、256 色，内容无裁切）：

| 时刻 | 截图 | 画面 |
|---|---|---|
| ≈0.8 s | `desktop-beat.png` | 纯桌面：洞还是亚像素的一点，透镜位移全域≈0，桌面文字一个字都没变形 |
| ≈3 s | `growing.png` | 洞约 47% 尺寸，金色盘正在成形（增益 0.54 / 1.1）；洞左侧的桌面文字已被弯成弧线 |
| ≈8 s | `settled.png` | 满尺寸稳态：桌面绕洞弯成弧线，盘最亮 |

## 时序

| 阶段 | 时长 | 驱动 |
|---|---|---|
| 纯桌面 | 0.6 s | `uHoleRadius` 0.0008（亚像素），`uGrow`=0 把中心的 Lissajous 漂移压住，洞钉在正中出生 |
| 生长 | 5.0 s | smootherstep 0→1：`uHoleRadius` 0.0008 → 0.125 |
| 稳态 | — | 与改动前完全一致（0.125 / gain 1.1 / 4200 K） |

盘亮度走同一条曲线：`uGain` 0.06 → 1.1、`uTemp` 2900 → 4200 K，所以"盘越来越亮"
和"洞越来越大"是同一次缓动，不是一个盖在另一个上面的淡入。亮度差可直接对比
`growing.png` 与 `settled.png`。

入场时钟是封面自己的 `t`：`cover.shown` 变真时归零，每次 `boss blackhole` 都重演；
隐藏时 30 fps Timer 停，`t` 不再走（长时间挂着不会把入场跳过去）。

透明窗口与入场都没有影响输入：入场期间键入 `deadbeef` 正常退出
（`tools/verify/exit.py` → `PASS: cover exited after typing deadbeef`，`focused=True`）。
