# 黑洞入场实测：先桌面，再盘先铺开，黑洞随后长大

`boss blackhole`（`--cover blackhole`）每次显示都从桌面开始：封面刚出现时是**原样的桌面**，
随后吸积盘先铺开、变亮，黑洞（阴影）在环内慢慢长大，最后落到稳态比例并开始随机游走。

## 画面

四帧来自同一次覆盖（全屏 1920×1080，`python tools/verify/shot.py <png> --at 1,2.5,5,12`
按封面出现后的墙钟时间连拍；存盘时缩到 1280×720、256 色，内容无裁切）：

| 时刻 | 截图 | 画面 |
|---|---|---|
| ≈1 s | `desktop-beat.png` | 纯桌面：洞是亚像素的一点，透镜位移全域≈0，桌面内容一个字都没变形 |
| ≈2.5 s | `disk-first.png` | 金色的环已经张开（外缘约 18 r_s），中心的黑洞只有一个小点——盘先出现 |
| ≈5 s | `growing.png` | 环更宽更亮（增益已接近 1.1），黑洞在环内长到约 1/3 尺寸 |
| ≈12 s | `settled.png` | 稳态比例（盘/阴影 ≈ 3.1:1）：桌面被弯成弧线，盘最亮；洞在这里已经随机游走到偏下的位置 |

## 时序

| 阶段 | 区间 | 驱动 |
|---|---|---|
| 纯桌面 | 0 – 0.8 s | `uHoleRadius` 0.0008（亚像素），盘还没有外缘可说 |
| 种子 | 0.8 – 1.4 s | 阴影 0.0008 → 0.02，盘外缘 5 → 11 r_s |
| 盘铺开 | 0.8 – 4.3 s | `uDiskOuter` 5 → 18 r_s、`uDiskInner` 1.8 → 3.6 r_s、`uGain` 0.06 → 1.1、`uTemp` 2900 → 4200 K |
| 黑洞成形 | 4.3 – 10.8 s | 阴影 0.02 → 0.125，同时盘外缘 18 → 8、内缘 → 1.8（回到稳态比例） |

盘/阴影的屏幕比例从种子期的约 6.9:1 收到稳态的 3.1:1，所以看起来是"环先铺开，黑点后长大"。
这不是两条独立的曲线：屏幕尺度只有一个 `W = B_CRIT / rh`，阴影半径恒等于 `rh`，盘的外缘
是 `rout × rh / B_CRIT`——想先看到盘，只能让 `rout`（r_s 单位）在早期更大。

稳态之后洞沿一条**有界随机游走**走：布朗加速度 + 阻尼 + 半径 0.045 外的软回拉，位置限制在
±0.08（屏高归一）、速度不超过 0.04/秒，所以它既不会绕回同一条轨迹，也不会跑到屏幕外。
入场时钟是封面自己的 `t`，`cover.shown` 变真时连游走一起归零，每次 `boss blackhole` 都重演。

## 清屏（Win+D）

黑洞是"桌面之上的透镜"，所以拍快照之前先把窗口清掉：逐个顶层窗口 `ShowWindow(SW_MINIMIZE)`
并记下 `WINDOWPLACEMENT`，对没权限下手的再用注入的 Win+D 兜底；退出时按记录的摆放位置逆序还原。

本机实测到的限制：开发用的预览进程是 **Medium 完整性级别**，而桌面上开着的应用是更高完整性，
Win32 的 UIPI 会同时挡掉 `ShowWindow` 和注入键，日志因此是

```
ra9fael.bosskey: show desktop: 6 windows up, 0 minimized, 6 left
```

即这一版要看宿主进程的权限：插件由 WinShun 启动，权限跟着 WinShun 走。真机上如果窗口没被清掉，
日志里就是上面这行；能看到 `N minimized`（不是 0）就说明清屏生效了。
